Campo de texto accesible y token-driven, aplicado como atributo sobre un <input> nativo. Soporta tamaños, estado deshabilitado/solo lectura, y expone un estado de error 100% automático a partir del FormControl que le conectes.

No hay toggle de prefix, clearable ni required porque HaInputText no los expone — estos 3 controles son toda la superficie real del componente.

Validación real con Angular Forms

El único estado semántico real de HaInputText es el de error, y es 100% automático: se calcula a partir de invalid && touched del FormControl conectado — no existe forma de setearlo a mano. Escribí un email inválido abajo y salí del campo (blur) para verlo.

@if (emailControl.invalid && emailControl.touched) {

Ingresá un email válido.

} @else {

Usamos este email para notificarte cambios en tu cuenta.

}

El host ES el <input> nativo

HaInputText se aplica como atributo (input[ha-input-text]) sobre un <input> nativo. No renderiza template propio (template: ''): no hay wrapper, no hay slots de label, prefix, suffix ni helper. Semántica nativa, teclado y foco vienen gratis, igual que en button[ha-button].

¿Y el label / texto de ayuda?

La librería reserva tokens de label y de hint (--ha-input-label-color, --ha-input-hint-color, etc.) aunque nunca dibuja esos elementos. Vos escribís tu propio <label> y párrafo de ayuda/error, y los estilizás con esos mismos tokens para que combinen visualmente sin que la librería posea ese markup.

Campo de email con label y error propios

Outputs

No expone @Output() propios — la integración es vía ControlValueAccessor ([formControl] / [(ngModel)]), igual que cualquier <input> nativo envuelto en Angular Forms.

Slots

No hay content projection: el componente no tiene template propio (template: ''), así que no puede proyectar <ng-content>. No existen slots de prefix/suffix.

Semántica nativa

Es un <input> nativo: edición de texto, selección, autocompletado y navegación por teclado funcionan sin manejo personalizado.

Foco por teclado

Angular CDK FocusMonitor distingue el origen del foco: el anillo extra (--ha-input-focus-ring) solo aparece cuando el foco se originó por teclado, no con clicks de mouse.

Atributos ARIA reales

El host bindea directamente aria-invalid, aria-disabled, aria-describedby y aria-label según los inputs y el estado del form control.
